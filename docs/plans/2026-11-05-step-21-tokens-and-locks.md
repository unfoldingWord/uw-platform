## Context

Today `packages/ui/tokens/` holds the prototype's tokens: `--uw-bg`, `--uw-ink`, `--uw-muted`, one tint per brand colour, Tailwind's spacing multiplier (`--spacing: 0.25rem`, so any multiple of 4 px exists), six text sizes and three radii. `tools/ui/tokens-agree.test.ts` proves every `@theme` value is a token, `no-hex.test.ts` that no colour literal sits outside the token files, `kindle.test.ts` that Kindle is used only by `HumanActionButton`. Nothing stops an arbitrary value (`p-[18px]`), and the fonts are named but never loaded.

The step replaces the token files with section 5's system, makes the Tailwind theme that system and nothing else, renames every class the components use to the new names, and adds the checks. It does not redesign a screen: step 24 does. Screens will look different after this step (new sizes, new colours) and are not judged until step 24.

## Rulings

| # | Ruling | Why | Cost if wrong |
|---|---|---|---|
| R21-1 | **Charts render on the server.** ECharts 6.1.0 renders inside workerd with `ssr: true` and the SVG renderer (spike, 2026-11-05: the render passes under the Workers pool). Its raw output carries a `<style>` element and `style="font-size…"` attributes, which `style-src 'self'` blocks. The chart component renders with sentinel colour names (`token-accent`), then a rewrite drops the `<style>` element and every `style` attribute and turns sentinel `fill`/`stroke` values and the text attributes into token classes (`fill-accent`, `text-xs`). A test proves the output has no `style` and no colour literal | ADR 0012 prefers the server; the rewrite is a pure function over ECharts' stable SVG shape, and no chart code reaches the browser | ECharts changes its SVG shape and the rewrite misses an attribute: the test fails on the upgrade, and the island path in ADR 0012 stays open |
| R21-2 | **ECharts' size.** Tree-shaken to bar, line, grid, tooltip and the SVG renderer: 565 KB minified, 193 KB gzipped, server only. The Worker is 1.04 MB gzipped before it | Measured with esbuild on the spike | A cold start parses more; within the 3 MB free and 10 MB paid limits |
| R21-3 | **Token names keep the `--uw-` prefix** (`--uw-canvas`, `--uw-text-3`, `--uw-inspire-400`). Tailwind's names are the role names (`bg-canvas`, `text-text-3`, `shadow-2`) | Section 5.2 names roles without a prefix; unprefixed `--text` collides with Tailwind's `--text-*` size namespace, and the existing checks key on `--uw-` | A rename; the checks name it |
| R21-4 | **Spacing in Tailwind is `0` and `1` to `8`,** the eight steps of section 5.3 plus zero; the sizes are `size-1` to `size-8` (`w-size-4`, `size-size-5`), the layout widths `side`, `inbox`, `aside`, `content`, `col-min`, `col-max`, and `flow` (the Flow diagram's existing 48 rem minimum, until step 24 rebuilds Flow). The theme starts from `--*: initial`, so every Tailwind default is gone | Tailwind 4 reads `--spacing-<key>` for `p-`, `m-`, `gap-`, `w-`, `h-`, `size-`; with the multiplier cleared, `p-9` and `gap-1.5` do not exist (verified, 2026-11-05) | A missing key: the class is silently not generated; step 25's screenshots show it |
| R21-5 | **Existing classes are renamed, not redesigned.** Spacing: 0.5 and 1 to `1`; 1.5 and 2 to `2`; 3 to `3`; 4 to `4`; 5 and 6 to `5`; 8 to `6`; 12 to `7`; 16 to `8`. Colour: `bg`→`canvas`, `ink`→`text`, `muted`→`text-3`, `link`→`accent-text`, `focus`→`accent`, `ocean` (text)→`accent-text`, `ocean` (stroke, fill, border, accent)→`accent`, `ocean-panel`→`side`, `ocean-panel-ink`→`text`, `inspire`→`accent`, `cultivate`→`ok`, `kindle`→`human`, each `-soft` to its role's `-soft`. Weight: `font-bold` and `font-extrabold`→`font-heavy`. Sizes keep their names (`text-sm` is now 13 px). The two grid templates become named utilities in `app.css` (`grid-cols-label`, `grid-cols-frame`) | Step 24 rewrites every screen; this step only has to compile onto the new tokens and keep the tests green | Screens look worse until step 24, which nobody judges before then |
| R21-6 | **Kindle's check follows the rename.** The human role (`human`, `human-text`, `human-soft`, `human-line`, `shadow-person`) is the one Kindle marks; the check reads utility prefixes and `var(--uw-human…)`, because the bare word `human` is a principal kind all over the code | `kindle.test.ts` matched the literal `kindle` | A false negative on a spelling the regex misses |
| R21-7 | **Fonts are a generated module,** like the stylesheet: `tools/ui/build-fonts.ts` reads the Latin `woff2` files of `@fontsource/nunito-sans` (400, 600, 800) and `@fontsource/jetbrains-mono` (400), both SIL OFL 1.1, and writes `packages/ui/generated/fonts.ts` with each file base64-encoded and a content hash in its path; `assetRoutes` serves them immutable and `type.css` declares the `@font-face` rules | The Worker serves its assets from generated modules (the stylesheet, the islands); there is no static-assets binding | Base64 inflates the bundle by a third; a static-assets binding can replace it later |
| R21-8 | **Icons: the Free fallback is the only artwork in the repository.** `packages/ui/components/icon.tsx` draws by name from `packages/ui/generated/icons.ts`. `tools/ui/build-icons.ts` writes that module from `@fortawesome/free-regular-svg-icons` and `@fortawesome/free-solid-svg-icons` (CC BY 4.0) for the names the screens use; with `--pro`, and only where `@fortawesome/pro-regular-svg-icons` and `pro-duotone-svg-icons` are installed, it writes Pro artwork instead, which a deploy build does just before bundling and nothing commits. The Pro packages are in no `package.json`. The committed module is checked to equal the Free build byte for byte, so a Pro module cannot pass `pnpm verify`. A name with no Free equivalent draws a same-size placeholder square | ADR 0013; the repository is public | The licence question in ADR 0013 stays Ian's; until it is answered every environment draws Free |

## Tasks

1. **The spike's record.** Remove the spike files; this plan and the tracker carry R21-1 and R21-2.
2. **UI-1, the scales.** `tools/ui/scales.ts`: the OKLCH generator of section 5.1 (pure functions, no dependency); `tools/ui/build-tokens.ts` writes `packages/ui/tokens/scales.css`, with `--check`. Tests: the brand hexes sit exactly on their steps; every value equals section 5.1's table; the committed file is the generator's output.
3. **UI-1, the roles and the rest.** `theme.css` (section 5.2's roles in light, system dark and forced dark, plus `--uw-highlight`, `--uw-depth`, `--uw-glow`, `--uw-glow-human`, `--uw-gridline`), `type.css`, `layout.css` (spacing, sizes, radius, layout widths), `shadow.css`. The contrast test of section 5.2: every text role on `canvas`, `surface`, `raised`, each text-on-soft pair and `on-accent` on `accent` and `human`, at least 4.5:1, both themes.
4. **UI-2, the theme and the rename.** `app.css` from `--*: initial`, every key a token; the class rename of R21-5 across `packages/ui/components` and `apps/uw-app`; the existing checks (`tokens-agree`, `generated-css`, `kindle`, the manifest colours) moved to the new names; `pnpm ui:css`.
5. **UI-2, the lock.** `tools/ui/arbitrary-values.test.ts`: no class with an arbitrary value (`-[…]`, an arbitrary variant such as `aria-[current=page]:` allowed) in a shipped source; no raw length (`px`, `rem`, `em`) or `box-shadow` in a shipped CSS file outside the token files, or in a `style` string; each proven against planted fixtures.
6. **UI-3, the fonts.** R21-7, the routes, the `@font-face` rules, and a test that each font is served with its type, the CSP's `font-src 'self'` covers its path, and no stylesheet or page names a font host.
7. **UI-4, the icons.** R21-8, with tests that the component draws a Free icon by name, a placeholder of the same size for an unknown one, an accessible name or `aria-hidden`, and that the committed module is the Free build (`build-icons.ts --check`).
8. **The chart component (R21-1).** `packages/ui/components/chart.ts`: `barsAndLine` and `sparkline` built on ECharts, the rewrite, and its test. Screens use it in step 24 (UI-14 is proven there).
9. **Record.** Tracker row 21 Built with evidence; the new dependencies (`echarts`, `@fontsource/nunito-sans`, `@fontsource/jetbrains-mono`, `@fortawesome/free-regular-svg-icons`, `@fortawesome/free-solid-svg-icons`) with what each replaces; `pnpm verify` green.
