# The design system is a calm page of five shapes, revealed on intent and edited in place

The tokens were locked (ADR 0011) and the look was the prototype's (ADR 0014), but nothing sat between them: no rule for how parts combine, when controls appear, or what a new screen starts from. Each screen chose for itself, and on 2026-11-24 the repository showed it: 13 different class strings on `<h2>`, 19 screen files drawing the card frame by hand beside the `Card` part, four local copies of the input style, and buttons as three exported class strings used more than fifty times, with no Button, Menu, Tooltip, Tabs, side panel or empty state part at all. The owner was not happy with how screens were turning out and asked for a system that keeps new work on pattern: cleaner and more modern, less clutter, hovers and pop-ups that reveal at the right time, "a bit of Notion's simple interface but with unfoldingWord flare". The system was drawn on a Claude Design canvas and is synced to `design-system/`.

**Decision.**

1. **A page, not a pile of cards.** Content sits on one white surface (`surface`), not on the grey `canvas` under bordered cards. Groups are separated by space (48 between sections, 24 from a heading to its content) and a `line-soft` hairline. A frame is kept for an object a person can open, move or act on: a queue card, a figure, a record. The `canvas` grey remains as the ground of a Board's lanes and of a figure row.
2. **Quiet until asked.** Row actions, menus and handles appear on hover and on focus-within; on a touch screen they are always shown. Never hidden: a gate, a refusal reason, the count of what waits on a person, and the view's one primary action.
3. **One loud thing per view.** At most one Inspire-filled primary button per view. Kindle orange marks a human action and nothing else (ADR 0007 stands); Save is that action, so Save is Kindle.
4. **Reveal in four steps.** Hover or focus shows a hint (row tint, row actions, a tooltip after 500 ms); a click opens an anchored menu or popover; opening an item shows a side panel that keeps the list in view and puts the item in the address (`?peek=`), so it works without JavaScript; only long work opens a full page. Reading never needs a modal. Menus and tooltips use the native `popover` attribute and render on the server.
5. **Five page shapes.** Every screen is a List, Document, Form, Board or Overview shape, each a component in `packages/ui/shapes/` whose slots a screen fills. A screen sets no grid, maximum width or page padding of its own. A sixth shape is a design change, as a new token is.
6. **Edit in place.** Editing is asked for, with a pencil on one property or an Edit button for the page or a section, so reading never makes a stray change. Once asked, the text a person is looking at becomes fields where it is: read rows are drawn at field height, the Edit button becomes Cancel and Save in the same place, and the formatting tools float over the content instead of pushing it. The sidebar, top bar, breadcrumb and title do not move. Esc or Cancel returns to reading and asks first when unsaved text is not in a working draft.
7. **Six text styles.** Document title (2xl, 800, Ocean), page title (xl, 800), section heading (md, 800), body (base, 400), meta (sm, 400, `text-3`) and field label (xs, 600, `text-3`, sentence case). Uppercase stays only in table heads. Badges and chips drop from 800 to 600.
8. **Three motion tokens.** 120 ms for a reveal, 160 ms for a popover, 200 ms for a panel, ease-out, and an instant swap under reduced motion. They are added to `packages/ui/tokens/effects.css` with the first part that uses them. No colour, spacing, type or radius token changes.
9. **One way to do each thing.** A screen imports its parts from `packages/ui`; it never writes a button, heading or card frame class string itself. A part that is missing is added to `packages/ui` first. A lint rule enforces this once the parts exist.

**What this overturns.**

- **ADR 0014**, in part. The prototype stays the authority for the frame: the Ocean sidebar grouped by area, the white top bar, the figure cards with an accent top rule and the pale lanes of compact cards. What goes is its canvas of bordered cards with a header and a body as the default container, its small uppercase labels, and its heavy badges. Unbuilt modules leave the sidebar for a "More" row instead of showing dimmed. The status bar folds into one dot in the top bar that opens the same facts. ADR 0011's scales and lock stand.
- **ADR 0026, point 3.** Edit mode no longer drops the sidebar, top bar and status bar or raises a sheet from the bottom of the window. It keeps its own address `/pages/:pageId/edit`, its form post and the editor island's hooks, so the read view still promises no field (CONTEXT: Read view) and still never loads the editor's 1 MB script (ADR 0017); it draws the read view's frame and layout, with the band's actions replaced by Cancel and Save, so moving between them changes what can be typed and not where anything is. Points 1, 2, 4 and 5 stand.

**Rejected.**

- **Always editable, as Notion is.** Every click becomes a cursor and a tap meant to select text can change it; there is no moment where a person chose to edit. The owner named stray edits as the reason to keep an explicit pencil or Edit.
- **Keep the focus-mode sheet of ADR 0026.** It repaints the whole page to change one word and loses the reader's place.
- **Edit on the read view's own address.** It would break the read view's promise and ship the editor script to every reader; a second address that draws the same layout keeps both.
- **The uW Generative Glass design system.** A different look from the app's, which would mean new tokens and a redesign rather than a cleanup. The owner chose to start from the app's own tokens.
- **Leaving the look alone and adding only a lint rule.** A rule against hand-written class strings needs the parts it points to; without Button, Menu and the shapes there is nothing to import instead.

**Consequences.** Screens move to the system one shape at a time, starting from Today, each pull request naming the shape it uses and the screen it started from. Until a screen moves, it keeps its ADR 0014 look, so the two looks will sit side by side for a while. The parts listed on the canvas (Button, IconButton, Menu, Tooltip, Tabs, Section, ListRow, ObjectCard, SidePanel, EmptyState) and the five shapes are added to `packages/ui` before the screens that use them. `design-system/` is the reference a person and an agent read before UI work; code never imports it and nobody hand-edits it (AGENTS.md rule 4). No screenshot check holds this look (PRD UI-16 was removed on 2026-11-23); a person checks it by eye in light, dark and phone width. Source: the owner on 2026-11-24.
