# Pages are edited in Milkdown Crepe, shared through a sync hub, and saved as markdown

The knowledge base (#175) replaces the Notion wiki. People there expect a formatted editor and to see each other typing. The platform's record of a page is its markdown, saved as numbered versions, and agents read and write that markdown directly. This ADR records how the two fit.

**Decision (2026-11-20, amended 2026-11-23).**

1. **Markdown stays the record, and is the editor's own source.** The edit screen uses Milkdown with its Crepe interface, as Crepe ships it: its block menu (`/`), its selection toolbar, tables, code blocks and images, in its own theme. Milkdown parses markdown and writes it back through remark, so the editor loads the page's markdown directly and Save sends the markdown it writes (`apps/uw-platform/islands/editor/crepe-editor.ts`). Two settings keep its output close to how pages are written: `-` for bullets and rules. A small plugin keeps the wiki's own syntax as it was typed, where remark would escape it: `[[links]]`, `![[embeds]]` and the `[!NOTE]` marker that opens a callout (`islands/editor/wiki-text.ts`). It writes them back verbatim, escaping only a `|` inside a table cell, and leaves an escaped `\[[` and anything typed in inline code as text. The round trip is tested through the real editor on sample pages (`apps/uw-platform/markdown/editor-round-trip.node.test.ts`).
2. **A page the editor would change opens as text.** The browser loads the page into the editor and compares the meaning of what the editor would write with what was saved, ignoring layout such as bullet markers, table padding, a reference link written inline, and an image's alt text, and counting which wiki links are live (`islands/editor/same-meaning.ts`). If they differ, the editor is put away and the page opens in the plain text field, with a line saying why. `?as=text` asks for the text field on purpose. No page is rewritten by being opened: Save sends the saved text unchanged when nothing was edited.
3. **The editor is its own script and stylesheet.** Crepe, ProseMirror, CodeMirror and Yjs are about 1.9 MB, and Crepe's theme about 38 KB. They load only on `/pages/:pageId/edit` (`generated/editor.ts`), not in the islands bundle every screen loads. Crepe's LaTeX feature is off, and code blocks know nine languages rather than CodeMirror's full set, which would more than double the script. The Content Security Policy still allows no inline style: the edit screen alone adds a per-response style nonce, which CodeMirror uses for the stylesheet it injects (`EditorView.cspNonce`), and table cells mark their alignment with `data-align`, not a `style` attribute; a table copied out of the editor carries its alignment as a style on the clipboard only (`islands/editor/table-align.ts`).
4. **A working draft is shared, per page version.** `PageDraft` is a Durable Object built on `y-partyserver`. Its name is `<pageId>.<version>.milkdown`. Everyone in edit mode on that version joins it over `GET /api/pages/:pageId/draft` (a WebSocket), which admits only a person who may write the page and only for the current version. The editor binds to the draft through Milkdown's collaboration plugin and `y-prosemirror`. In a shared draft the editor's own undo history is removed, so Undo takes back only the person's own edits, through the draft's undo manager. The draft counts as changed only after the person types, pastes, drops or clicks in it, not when the editor first lays out the joined text. If the draft cannot be reached, the editor is rebuilt without sharing, with its own undo, and the person edits alone.
5. **Nothing reaches readers until Save.** Save is the same form post and the same `update_page` command as before, with the markdown of the draft and a Yjs snapshot of the draft as the saver saw it. The page moves to the next version and the old version's sync hub is asked to close. It closes, and deletes the draft, only if its document equals that snapshot. If anyone typed or deleted after the snapshot was taken, it keeps the draft and tells the people in it that their latest changes were not saved. Typing and Save stay off until the browser has joined the draft. Discard asks first, naming how many others it affects, then sets the draft back to the saved text for everyone in it.
6. **The first content is the same for everyone.** The first person into an empty sync hub fills it from the saved page. Two people arriving together would both fill it, so the fill is built with a fixed Yjs client id: both produce the same bytes, and applying them twice changes nothing (`islands/editor/collaboration.test.ts`).
7. **A save from elsewhere is caught at Save, and announced before it.** An agent, the API, a restore or another tab can save a newer version while a draft is open. The browser checks the page's version every 30 seconds while a draft is open and tells the people in it when it has moved on. The draft's Save is then refused `stale_version`, as it always was, and the screen keeps what was typed and edits it alone, not in a shared draft, so two people's refused text is never merged into one.
8. **A draft socket is admitted for a bounded time.** The Worker checks write access when the socket opens and passes the hub an end time: five minutes, or sooner if the grant that allows writing expires. The hub refuses messages after that and closes the socket; the browser reconnects, and the Worker checks access again. A revoked grant therefore stops a person's edits within five minutes.
9. **Links to pages and files are added from the editor.** Typing `[[` opens a picker over the page index: choosing a page inserts a link to `/pages/<id>`, or an `![[embed]]`. Crepe's `/` menu also offers "Link to a page" and "Picture or file". Pictures added through Crepe's image block, and files added through the upload control, are stored as page files and written into the markdown.

**Rejected.**

- **An editor with its own document shape, converted to and from markdown.** The first build of this ADR used one, with a markdown-to-HTML converter on load and an HTML-to-markdown converter on Save. Every conversion was a place to lose formatting, the server had to decide in advance which pages the editor could hold, and markdown pasted into the editor arrived as plain text. An editor whose source is markdown removes both converters.
- **Save the Yjs document, or the editor's JSON, as the record.** Agents, search, links, embeds and history all read markdown. A second format would need a converter on every read and would make the versions unreadable outside the editor.
- **Autosave straight to the page, as Notion does.** The owner asked that a page not change by being opened or typed in. Readers and agents would also see half-written procedures.
- **Merge an agent's write into the open draft.** #175 asks for this if markdown can become a Yjs change inside the Durable Object. That needs the editor's parser and schema to run in the Workers runtime. It is not built and has not been measured with this editor, so the draft is told instead (point 7).
- **One sync hub per page, reset on Save.** A browser that still held the old draft would merge it into the new one when it reconnected. A hub per version cannot be rejoined with stale text: the socket is refused once the version moves on.
- **Fill the first content on the server.** The Worker would have to run the editor's parser. The fixed client id gives the same guarantee with no editor code in the Worker.
- **Hocuspocus or a hosted collaboration service.** Either adds a server or a vendor outside Cloudflare. `y-partyserver` runs in the Worker the app already deploys.
- **Restyle Crepe in the platform's tokens now.** The first Milkdown change uses Crepe's own theme; matching the design system is later work.

**Consequences.**

- A working draft lives in its sync hub's storage, not in Postgres. It is kept until it is saved, discarded, or has been idle for 30 days.
- Drafts opened before 2026-11-23 were stored in the previous editor's document shape, under hubs named `<pageId>.<version>`. The new editor never opens them, so text typed in one and not saved is not carried over.
- Crepe's image block stores a picture's display size in its alt text, so an edited page writes `![1.00](/api/files/…)` where it had `![Alt text](/api/files/…)`, and an embed written as `![Title](/pages/…)` loses its title the same way. The owner accepted this for the first Milkdown change. A video file shows in the editor as a broken picture, though it still plays on the read view.
- The read view asks the sync hub whether a draft is open, for people who may edit, and says so. That is one Durable Object call on those page views. It asks the hub of the current version only, so a draft kept on an older version (point 5 or 7) is not announced there.
- Rendering is not cached. Measured on 2026-11-21 in the local Workers runtime, a 147,212-character page renders in 1.4 to 1.6 s per read view, database included. That fits a paid plan's 30 s CPU limit but is slow for a reader; caching the rendered HTML per page version is the next step if real pages are that long.
- A person's name beside their cursor is sent by their own browser. Only people who may write the page can connect, so the worst a person can do is mislabel their own cursor.
- A sync hub holds its sockets open without hibernation, so it is billed while people are in edit mode.
- A draft is stored as one value. Durable Object storage limits one value to 2 MB; a page's markdown is limited to 1 MB, so an ordinary draft fits, but a very long page with a long editing history might not, and its draft would then stop being stored. This has not been measured.
- The `PAGE_DRAFT` binding and its `v3` migration are in both wrangler files. Where the binding is absent the edit screen offers no shared draft and people edit alone.
