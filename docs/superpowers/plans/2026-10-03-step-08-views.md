# Step 8: Views Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give people the six harness screens (Home "waiting on me", Flow, Board, Gates, the item play-by-play and the `/health` agent plane) inside the shared shell, live on a wake, installable, under a Content-Security-Policy, each proven by tests named for its requirement.

**Architecture:** Every screen is server-rendered by Hono JSX from one new kernel read family, `kernel.views` (pure, in `packages/harness/views/`, over new Store read members), so a screen shows exactly what `can()` lets the person read. A small islands bundle (built by esbuild into a committed generated module, served from `/assets/`) does two things in the browser: it posts the forms marked `data-command` to the existing command API with a fresh `requestId` and shows the outcome in place, and it keeps a live session per harness (the existing `islands/live/session.ts`) whose wake re-renders `<main>` from a fragment GET and morphs it with idiomorph. `/health` moves behind Access and gains the agent plane, whose exported indicator function is the same one `get_health` calls; a public `/health/probe` keeps the deploy probe working. The Gates view renders the gate view the kernel already assembles (`assembleShipInput` through `shipPreview`) plus the Reviewer findings, which the read model now stores.

**Tech Stack:** TypeScript strict, Hono 4 JSX, Zod 4, Drizzle over Postgres, Tailwind 4 over the brand tokens, esbuild 0.28.1 (islands bundle), idiomorph 0.8.0 (DOM morph), partysocket (existing), jsdom 30 and axe-core 4.13 (tests), Vitest (Node and Workers pools), PGlite in the sim.

**Spec:** `docs/PRD.md` (approved; no brainstorm, no approval step). Requirements covered: **WB-4, WB-5, WB-6, WB-7, WB-8, WB-9, WB-10, WB-12**. Carries planned here (each closed in Task 10 with its commit): WB-6 the Gates view shows the assembled ship-rule input and fills `GateFacts`' resolved review providers and derived-now tier, the head beside the declaration (step 5, step 6 Task 20, S5-R40); WB-10 `get_health` switches its `not_wired` indicators to WB-10's exported queries (step 4, R24); WB-10 a stalled GitHub sweep indicator (step 5); WB-10/WB-11 `/health` and the pending page move into the shell (step 6 Task 18); SECURITY a Content-Security-Policy with the stable hashes of the inline theme scripts (step 6 Task 18); WB-12 completed (step 6 left it partial); WB-3 a periodic read while the socket is open, where a view wants it (step 6 Task 16); the evidence label's definition visible to a touch user (step 6 Task 19 not-verified row).

```ts
import type { MiddlewareHandler } from 'hono';
import { inlineScripts } from '@uw/ui/components/inline-scripts.ts';
import type { AppEnv } from '../deps.ts';

let hashes: Promise<readonly string[]> | null = null;

async function sha256(text: string): Promise<string> {
  const digest = await crypto.subtle.digest('SHA-256', new TextEncoder().encode(text));
  return `'sha256-${btoa(String.fromCharCode(...new Uint8Array(digest)))}'`;
}

export async function contentSecurityPolicy(host: string): Promise<string> {
  hashes ??= Promise.all(inlineScripts.map(sha256));
  const scripts = (await hashes).join(' ');
  return [
    "default-src 'none'",
    `script-src 'self' ${scripts}`,
    "style-src 'self'",
    "img-src 'self'",
    "font-src 'self'",
    `connect-src 'self' wss://${host}`,
    "manifest-src 'self'",
    "worker-src 'self'",
    "base-uri 'none'",
    "form-action 'self'",
    "frame-ancestors 'none'",
  ].join('; ');
}

export function securityHeaders(): MiddlewareHandler<AppEnv> {
  return async (c, next) => {
    await next();
    const host = new URL(c.req.url).host;
    c.header('content-security-policy', await contentSecurityPolicy(host));
    c.header('x-content-type-options', 'nosniff');
    c.header('referrer-policy', 'same-origin');
  };
}
```

`host` comes from the request URL only after the router accepted the request; a host with a character outside `[A-Za-z0-9.:-]` is replaced by `'self'` alone in `connect-src`.
