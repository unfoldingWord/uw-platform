Edit where you read. Nothing moves.

Editing is something you ask for, with a pencil or an Edit button, so reading never makes a stray change. Once you ask, the same page becomes editable in the same place. The sidebar, the title and every line of text stay where they were.

Always editable (Notion)

Stray edits

Every click is a cursor. A tap to select text can change it. No moment where you chose to edit.

Separate edit screen (today, ADR 0026)

The page repaints

Sidebar and top bar vanish, a sheet rises, the title moves. You lose your place to make a one-word fix.

Edit in place (proposed)

Ask, then edit right there

Pencil or Edit turns the text you are looking at into fields, in the same spot. Save or Esc returns it.

01

Read rows are drawn at field height

A property row is 36 tall and the title box 46 tall in both modes. A field differs from text only by a faint outline, so switching mode shifts nothing.

02

The Edit button turns into Cancel and Save

Same spot, same reserved width. Comment and More step aside while editing. Save is Kindle, because saving is the human act; Edit is a secondary button with a pencil.

03

Scope matches the reach

A pencil on hover edits one property and saves on its own check mark or Enter. Edit opens the whole page. A record's section can have its own Edit. Only one scope is open at a time.

04

Tools float, never push

The formatting pill sits over the bottom of the content. The "Editing" status uses a slot the top bar already reserves. Nothing inserts above the text.

05

Leaving is always safe

Esc or Cancel goes back to reading. With unsaved text and no working draft, it asks first. A refused save keeps the fields open with the reason under Save.

06

Keeps ADR 0026's reasons

The edit view can keep its own /edit address, its form post and its lazily loaded editor. It just renders the read view's frame and layout, so the read view still has no field and still skips the 1 MB script.
